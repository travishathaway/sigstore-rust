# Proposal: py-sigstore-rust-bindings

## What

Add a new crate `crates/sigstore-python/` to the workspace that exposes the sigstore-rust library as a Python extension module named `py_sigstore_rust`, published to PyPI as `py-sigstore-rust`.

The binding provides a Pythonic facade over the existing Rust crates — covering artifact verification, bundle parsing, trusted root management, OIDC identity token handling, and artifact signing — using PyO3 and Maturin.

## Why

The sigstore ecosystem has a Python client (`sigstore` on PyPI), but it is a pure-Python implementation. Package managers written in Python (pip, conda, rattler-build, etc.) that integrate with sigstore for supply-chain verification would benefit from a Rust-backed implementation that is:

- **Faster**: cryptographic operations run at native speed
- **Consistent**: shares the same verification logic as the Rust library used by rattler and similar tools
- **Well-typed**: ships `.pyi` stubs generated at compile time
- **Easy to distribute**: abi3 wheels compiled once per platform, no Python version matrix

## Goals

- Expose the full verification workflow (verify artifact bytes against a sigstore bundle using an identity policy)
- Expose the full signing workflow (sign artifact bytes using an ambient or provided OIDC token)
- Ship typed Python stubs (`.pyi`) generated by `pyo3-stub-gen`
- Build abi3 wheels for Linux x86_64/aarch64, macOS x86_64/aarch64, Windows x86_64
- Provide a Pythonic facade API that feels familiar to users of the official `sigstore` Python client
- Live as a first-class crate in the existing workspace (no separate repo)

## Non-Goals

- Drop-in API compatibility with the official `sigstore` Python client
- Exposing low-level crate internals (RekorClient, FulcioClient, Merkle, TUF internals)
- Browser-based OIDC OAuth flow (ambient credential detection covers CI use cases)
- Composite policy types (AllOf, AnyOf) in v1 — Identity only
- Async Python API — all bindings are synchronous (Tokio runtime embedded internally)
- FIPS-mode crypto

## Approach

A new `crates/sigstore-python/` crate with:
- `[lib] crate-type = ["cdylib", "rlib"]` for the extension module and stub generation binary
- PyO3 0.29 with `abi3-py310` feature
- `pyo3-stub-gen` 0.23 for compile-time stub generation
- Embedded `tokio::runtime::Runtime` (via `OnceLock`) for async→sync bridging
- A `python/py_sigstore_rust/` mixed-layout directory for the pure-Python facade layer
- A `src/bin/stub_gen.rs` binary that generates `.pyi` stubs
- Maturin as the build backend (`pyproject.toml` in the crate directory)
